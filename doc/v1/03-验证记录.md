## 注入修正（registry.yaml，仅数据）

**根因**：模板 `workflows/ltx-2.3-i2v.json` 是两段式管线：
`320.290` 重排首帧到目标 WxH → `320.292/320.294`（`a/2`）→ `320.295` 半分辨率生成 → `320.287 LTXVLatentUpsampler`（×2 上采样器 `ltx-2.3-spatial-upscaler-x2-1.1`）→ 全分辨率精修出片。
原 registry 把 `width/height` 同时注入 `320.290`（图像重排）和 `320.295`（一段 latent），**字面量覆盖了 `a/2` 链接**，两段都在目标分辨率，经 ×2 上采样后输出恒为 2× 目标（480×864 → 960×1728）。

**修正**（commit 见下）：`inject.width/height` 仅保留 `320.290` 的 `resize_type.width/height`，`320.295` 的 width/height 恢复走模板 `a/2` 链接。离线构建图验证：

```
320.290 -> {"resize_type.width": 480, "resize_type.height": 864, ...}
320.295 -> {"width": ["320.292", 1], "height": ["320.294", 1], "length": 76, ...}
```

回归：`pytest -q` → **31 passed**。gateway 为每请求 `load_registry`，改 yaml 即生效，无需重启。

## MiniMax-H3 探测结论（Task 9）

日期：2026-11-08　分支：feat/v1

**探测方式**：Task 5 真机 `/prompt` 逐节点校验（26 节点模板结构通过，缺文件在校验阶段即定位）+ 本机模型目录文件核对（未启动生成，探测结果由文件缺失直接决定）。

**结论**：`minimax-h3-local` 维持 `available: false`。

**原因（缺 UNET 文件）**：
- 模板 `105.6`(UNETLoader) 要求 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`，本机所有 `diffusion_models` 目录为 0 文件。
- 本机仅有用户已下载的 `qwen3vl_32b_heretic_minimax_h3_nvfp4.safetensors`（heretic 发行版），与模板所需发行版不匹配（模板 CLIP 侧要求 `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`，名称亦不同）。
- 其余待补齐文件：VAE `minimax_h3_video_vae_int8_convrot.safetensors`、`minimax_h3_audio_vae_fp32.safetensors`，LoRA `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`。

**附加风险**：nvfp4 量化在本机 Ampere 架构（RTX A2000 8GB）上的支持存疑（nvfp4 官方面向 Blackwell+），即使补齐文件也可能不可用或需回退量化方案。

**注入点回填**（本次同时完成，仅数据修正）：转换后模板没有独立 PrimitiveStringMultiline，提示词直挂在 `105.104`(MiniMaxH3ImageToVideo) 的 `prompt` 字段；图像注入 `114`(LoadImage).`image` 不变。已写入 `registry.yaml` 并由 `test_registry.py` 守卫。

**恢复路径**：下载对应发行版的 UNET/CLIP/VAE/LoRA 文件 → 在 ComfyUI 桌面版手动跑通该模板（确认 nvfp4 在本卡可用）→ `registry.yaml` 置 `available: true` 并跑 minimax 冒烟。
