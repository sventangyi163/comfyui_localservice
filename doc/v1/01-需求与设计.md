## 1. 背景与目标

本机 ComfyUI 桌面版（`E:\comfy-desktop`，v0.42.1，端口 8188，常驻）已跑通 LTX-2.3 图生视频。
目标是把该 ComfyUI 实例包装成一个**独立的图生视频（I2V）服务**：对外提供与火山引擎 Ark 内容生成任务 API **同构**的接口，使外部应用（首个接入方：AI互动短剧项目）把本机 ComfyUI 当作一个可切换的"图生视频大模型"使用，并能**在启动项目时指定调用哪个视频模型**。

**v1 范围**：仅本地 ComfyUI 模型（LTX-2.3 主线 + MINIMAX-H3 探测注册）。云端 API 代理、鉴权、服务化自启留给 v2。

**不在范围内**：文生图（t2i）槽位、LLM 槽位、互动实时（低延迟）生成——本地 LTX 生成一条 5s 720p 约 5~6 分钟，定位是离线管线。

## 2. 需求

### 2.1 功能需求

| # | 需求 | 说明 |
|---|---|---|
| R1 | Ark 同构任务 API | 提交→轮询→下载三段式，请求/响应结构与 Ark `contents/generations/tasks` 兼容，接入方现有提交/轮询/下载代码零改动 |
| R2 | 模型注册表 | 模型名→工作流模板映射；v1 注册 `ltx-2.3-local`（已跑通）与 `minimax-h3-local`（探测注册，可用性如实标记）；新增/更换模型不改网关代码 |
| R3 | 参数注入 | 每次任务注入：首帧图、提示词、时长（秒）、分辨率档位、模型文件名 |
| R4 | 项目级模型指定 | 提交 body 的 `model` 字段即模型选择；`GET /models` 供外部启动项目时枚举校验 |
| R5 | 任意画幅跟随首帧 | 16:9 / 9:16 / 1:1 等跟随首帧图长宽比；resolution 档位映射到**短边**像素；宽高对齐模型要求的整数倍 |
| R6 | 任务状态持久化 | 任务表落盘（SQLite），网关重启后未完成任务置 failed（外部可重试） |
| R7 | 进度可见 | 轮询响应附 best-effort `progress`（0-100，来自 ComfyUI WebSocket/队列位置） |

### 2.2 非功能需求

- 部署：本机 `127.0.0.1`，免鉴权（预留 token 字段）；并发任务直接进 ComfyUI 队列（ComfyUI 串行执行，天然排队）
- 性能基准：5s 720p 一条 ≤ 8 分钟（实测基准 333s，含 2x 上采样）
- 网关自身轻量：仅依赖 fastapi/uvicorn/httpx，独立 venv

## 3. 总体架构

```
   │ base_url=http://127.0.0.1:8300         │  Ark 同构任务 API
```


## 4. API 规格

### 4.1 提交任务

`POST /contents/generations/tasks`

```json
{
  "model": "ltx-2.3-local",
  "content": [
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,..." }},
    {"type": "text", "text": "镜头提示词……"}
  ],
  "duration": 5,
  "resolution": "720p"
}
```

- `model`：必填，须为注册表中条目
- `content`：首帧图 data URL 必填（png/jpg/webp）+ 提示词文本必填
- `duration`：整数秒，须在模型 `duration_range` 内（LTX：3–8）
- `resolution`：`480p | 540p | 720p`（短边像素映射 480/540/720），默认 720p
- 画幅不传参，**跟随首帧图**（与 Ark i2v 行为一致）

响应 `200`：

```json
{"id": "t_20261108_153000_a1b2", "model": "ltx-2.3-local"}
```

错误：`400` 参数/模型/时长/分辨率不合法（`{"error": {"message": "..."}}`）；`503` ComfyUI 不可达。

### 4.2 轮询任务

`GET /contents/generations/tasks/{id}`

```json
{
  "id": "t_...",
  "model": "ltx-2.3-local",
  "status": "running",
  "progress": 42,
  "created_at": "2026-11-08T15:30:00+08:00",
  "content": {},
  "error": null
}
```

- `status`：`queued`（ComfyUI 队列中）→ `running`（执行中）→ `succeeded` | `failed`
- 成功时 `content.video_url` = `http://127.0.0.1:8300/files/{id}.mp4`；失败时 `error.message` 带摘要（ComfyUI execution error 或 timeout）
- ComfyUI 瞬时不可达：返回缓存状态不误报失败；超过任务超时上限（默认 1800s，注册表按模型可覆盖）才置 `failed("timeout")`
- `404` 任务不存在

### 4.3 下载视频

`GET /files/{id}.mp4` → `video/mp4` 字节流。仅 succeeded 任务可下载。

### 4.4 模型列表（扩展端点）

`GET /models`

```json
{"models": [
  {"name": "ltx-2.3-local", "kind": "i2v", "available": true,
   "duration_range": [3, 8], "resolutions": ["480p", "540p", "720p"],
   "aspects": ["9:16", "16:9", "1:1"]},
  {"name": "minimax-h3-local", "kind": "i2v", "available": false, "...": "..."}
]}
```

`available` 由网关启动时探测一次（模型文件存在 + 模板节点可解析），`/models` 返回该探测结果；运行期单条任务失败不回写该标记。

## 5. 模型注册表

### 5.1 条目结构（registry.yaml）

```yaml
- name: ltx-2.3-local
  template: workflows/ltx-2.3-i2v.json
  available: true            # 探测后回写；探测失败如实置 false
  duration_range: [3, 8]
  fps: 24
  resolutions: {480p: 480, 540p: 540, 720p: 720}   # 短边像素
  dims_multiple: 32          # 宽高对齐步进
  aspects: ["9:16", "16:9", "1:1"]
  timeout_s: 1800
  inject:                    # 注入点映射：参数 → 模板节点 id + 字段
    image:        {node: "12", field: "image"}
    prompt:       {node: "6",  field: "text"}
    width:        {node: "31", field: "width"}
    height:       {node: "31", field: "height"}
    length_frames:{node: "31", field: "length"}
```

- `inject` 的节点 id 来自导出的模板文件，是**数据不是代码**——换模型/换精度只改 yaml + 加模板 JSON
- 帧数 = `duration × fps`；宽高 = 首帧长宽比 × 短边档位，再对齐 `dims_multiple`

### 5.3 更换模型 / 更换精度的操作路径（不改网关代码）

1. 模型文件放入 models 目录（如需新自定义节点，先用 Manager 安装并在桌面版跑通一条工作流）
2. 工作流导出 API 格式 JSON，放入 `workflows/`
3. `registry.yaml` 加条目（含注入点映射与约束）
4. 外部项目把 i2v 槽位 `model` 改为新名称即生效；fp8 与原精度可并存注册，按项目选用

## 6. 数据流（一次生成）

1. 短剧 `video_step` → `resolve_slot("i2v")` 得 `{provider: ark_local, base_url, model}` → 调用**现有** `submit_i2v` / `poll_task` / `download`
2. 网关提交：校验注册表约束 → 解码首帧图（读像素得画幅）→ `POST /upload/image` → 深拷贝模板并注入参数 → `POST /prompt` 得 `prompt_id` → 任务表落盘
3. 网关轮询：查 `/history/{prompt_id}` + WebSocket 进度 → 状态映射；完成后从 history outputs 定位 mp4 → 经 `/view` 拷入 `files/{task_id}.mp4` → `succeeded` + `video_url`
4. 短剧侧 poller 拿 `video_url` → download → artifact 入库（现有逻辑不动）

## 7. 与 AI互动短剧 的集成

短剧侧改动（详见其 `doc/v1/16-本地i2v网关Provider.md`）：

1. **槽位配置**（数据，非代码）：i2v 槽位项目级覆盖，`provider=ark_local`、`base_url=http://127.0.0.1:8300`、`model=ltx-2.3-local`、`timeout_s=1800`
2. **微补丁**：`ark_tasks._headers` 对 `provider=="ark_local"` 免 API key 校验；`estimate_cost` 对本地模型记 0 成本
3. 提交/轮询/下载/video_step 代码路径**零改动**

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| ComfyUI 提交时不可达 | 提交返回 `503` + message |
| ComfyUI 执行报错 | 任务 `failed`，`error.message` 取 `/history` execution error 摘要 |
| ComfyUI 轮询瞬时不可达 | 返回缓存状态（queued/running），不误报 |
| 超过模型 `timeout_s` | `failed("timeout")` |
| duration/resolution/画幅越界 | 提交时 `400` |
| 网关重启 | 任务表未完成项置 `failed("gateway restart")`，可重提 |
| 网关运行期 ComfyUI 被手工任务占用 | 排队等待（同一队列），不影响正确性 |

## 9. 测试与验收

- **单测**：模板注入（含画幅/对齐计算）、注册表约束校验、状态映射、任务表重启恢复
- **集成**：真实 ComfyUI 跑通一条 3s 480p（最快档）
- **端到端验收**：
  1. curl 提交→轮询→下载全链路成功，5s 720p ≤ 8 分钟
  2. 16:9 与 9:16 首帧各一条，输出画幅正确（±32px 对齐容差）
  3. `minimax-h3-local` 探测结果如实（可用 / unavailable），不影响 LTX 主线
  4. 短剧槽位切本地后单分镜全自动出片，短剧侧代码路径零改动
  5. 越界参数返回 400；杀掉网关重启后任务状态正确

## 12. 风险与开放问题

| # | 风险 | 应对 |
|---|---|---|
| 1 | MINIMAX-H3 为 nvfp4 量化，A2000（Ampere）原生支持存疑，可能退化为解量化加载（显存/速度劣化） | 实施期实测；跑不通则注册表 `available: false`，不影响主线 |
| 2 | 29GB 权重 / 8GB 显存，动态加载+卸载已验证可行但速度受限（~333s/条） | 分辨率档位 480p/540p 可提速；对延迟敏感的场景留给 v2 云端代理 |
| 3 | ComfyUI 升级导致模板节点变化 | 模板随项目走（API 格式 JSON 固定节点 id）；升级后跑回归用例（§9 集成项） |
| 4 | 网关与用户手工使用同一 ComfyUI 队列互相排队 | 运维约定：批量生产期间避免手工提交；v2 可考虑第二实例 |
